# 문서 초안 집필 규칙

## 파일 구조
```
drafts/{category}/{slug}.md
```
카테고리 폴더명 = 최종 URL 경로. `/help/{category}/{slug}` 로 그대로 연결됩니다.

## 프론트매터
D1 스키마와 1:1 대응합니다. 어드민 임포트 시 그대로 매핑됩니다.

```yaml
---
title: 문서 제목
slug: url-slug
category: pricing
type: article          # article | notice
summary: 검색 결과·메타 디스크립션·AI 요약에 쓰이는 1~2문장
env: windows           # windows | chrome | app | bizmanager | all
audience: owner        # owner | hq
tags: [pricing, 결제]
status: draft
---
```

## 톤
- **마스코트 "올리" 사용하지 않습니다.** 캐릭터 화자, 이모지 남발, "~해드릴게요 🥰" 톤을 쓰지 않습니다.
- 간결한 존댓말 설명체. 오터 웹사이트 톤에 맞춥니다.
- 사장님이 주 독자입니다. 내부 용어를 그대로 쓰지 않습니다.

## 본문 규칙

1. **스크린샷 없이 읽어도 말이 되어야 합니다.** 이미지는 보조입니다.
   기존 노션의 가장 큰 실패가 내용을 스크린샷 안에만 넣은 것이었습니다.
2. **한 문서 = 한 작업.**
3. **조건절을 본문에 섞지 않습니다.** 기본값 하나로 쓰고, 예외는 하단 `**예외 안내**` 블록에 모읍니다.
4. **첫 문단이 요약입니다.** 검색 결과와 AI 인용에 이 부분이 쓰입니다.

## 제목 단계 (중요)

문서 우측 목차는 `##`과 `###`만 읽습니다. **절차의 각 단계는 반드시 `###` 소제목으로 씁니다.**

```markdown
## 주문 입력하기        ← 우측 목차 1단
### 1. 메뉴 선택        ← 우측 목차 2단
### 2. 가맹점 선택
```

`**1. 메뉴 선택**` 처럼 굵은 글씨로 쓰면 목차에 잡히지 않아 긴 문서에서 길을 잃습니다.
굵은 글씨는 단계 제목이 아니라 **본문 안의 강조**에만 씁니다.

## 굵게 표기 (중요)

**닫는 `**` 바로 뒤에 조사를 붙이지 마세요.** 마크다운 표준(CommonMark)에서
닫는 `**` 앞이 문장부호(`]`, `)`, `?` 등)이고 뒤가 글자면 **굵게로 인식되지 않습니다.**

```markdown
❌ **[매장관리]**를 누릅니다        → 화면에 `**[매장관리]**를` 그대로 노출
✅ **[매장관리]** 버튼을 누릅니다
```

굵게 뒤에 **공백 + 명사**를 넣습니다. 문장도 더 명확해집니다.

| 상황 | 붙일 명사 |
|---|---|
| 클릭하는 버튼 | `버튼을` |
| 좌측/상단 메뉴 | `메뉴를` |
| 화면 상단 탭 | `탭에서` |
| 토글·상태값 | `상태로` |
| 기능 이름 | `기능을` |
| 링크 | `링크를` |

원래 마지막 글자가 글자·숫자면 문제가 없습니다. `**조리시간**을 선택합니다`는 정상입니다.
괄호·따옴표로 감싼 경우만 주의하면 됩니다.

2026-08-25에 이 규칙으로 31건을 일괄 정리했습니다.

## 정렬 순서

프론트매터의 `order` 값이 좌측 트리와 카테고리 내 순서를 정합니다.
새 문서를 추가할 때 같은 카테고리 안에서 읽는 순서대로 번호를 매깁니다. (D1 `sort_order` 컬럼)

## 예외 안내 서식
문서 맨 아래, 구분선 뒤에 둡니다. 렌더러가 자동으로 박스 처리합니다.

```markdown
---

**예외 안내**

- **조건** — 설명.
```

## 미확인 표기
근거 없이 쓰지 않습니다. 확인이 필요한 부분은 본문에 남기지 말고 주석으로 표시합니다.

```markdown
<!-- 확인필요: VAT 포함 여부 -->
```

집필 시점에 확인된 사실만 본문에 넣습니다. `IA.md` 9장의 자료 충돌 5건은 해소 전까지 본문에 단정해 쓰지 않습니다.
